# Decisions

Choices the spec left open, and why. Follow these unless a later entry here
replaces one. When you make a new call the spec doesn't cover, add it here.

## M1

1. **Unknown data keeps raw text.** `Unknown` entities, raw tables, raw
   sections, header variables and `extra` lists store each value as the
   original text (`Pair { code, raw }`), not as a parsed `Value`. This lets
   the M3 writer reproduce unknown data byte-for-byte. `Unknown::group_codes()`
   and `Pair::value()` give the typed view. (The spec sketched
   `Vec<(i16, Value)>`.)
2. **Header values are accessors.** `Header` holds every variable in file
   order; `version()`, `insunits()`, `extmin()` etc. read from that list, so
   there is one source of truth.
3. **Known entities keep leftovers in `extra`.** Codes a parsed entity doesn't
   use (XDATA, `102 {...}` groups, `999` comments, unrecognised codes) go into
   `Entity::extra` in file order. Subclass markers (`100`) are dropped; the
   writer regenerates them. `Layer::extra` works the same way.
4. **Malformed → `Unknown` + warning.** A bad number, missing required field,
   negative radius, or invalid colour, lineweight, handle or flag turns a known
   entity into `Unknown` (all pairs kept) with a warning. Zero radius is
   accepted.
5. **Duplicate table names:** the first entry wins; the duplicate is kept in
   `Table::unparsed` with a warning.
6. **Damaged files:** a tokenizer error after the first `0 SECTION` keeps
   what was read plus a warning; garbage before any section is
   `DxfError::NotDxf` or a syntax error. Missing `ENDSEC`, `ENDTAB` and `EOF`
   are warnings.
7. **Arc angles** are stored in degrees, as in the file.
8. **`999` comments outside sections** are kept as stray records, without a
   warning (the format allows them anywhere). *(Changed in M2 part B; they
   were dropped before.)*
9. **Licence:** `MIT OR Apache-2.0`, with `LICENSE-MIT` and `LICENSE-APACHE`.
10. **Versions:** `Version` covers R12, R13, R14 and 2000–2018 (R13/R14
    added in M2). Other `$ACADVER` values still load, with a warning;
    `Header::acadver()` returns the raw string.
11. **Encoding:** replaced by M2 part B decisions 4–9 (the Latin-1 fallback
    is gone).

Also settled:

- **No `dxf` crate.** The reader is written from scratch with no dependencies;
  the spec's "evaluate the `dxf` crate" step was dropped after M1.
- **Corpus:** `tests/corpus/` is generated by `tools/gen_corpus.py` (keep them
  in sync). Files that can't be redistributed go in the git-ignored
  `tests/corpus-private/`; the corpus tests load them when present.

## Corpus (before M2)

- **All corpus drawings are our own.** `tools/gen_sources.py` draws 13 drawings
  with ezdxf; `tools/convert_corpus.sh` re-saves them through other writers.
  No third-party drawings, so everything in `tests/corpus/` is redistributable.
- **Writers and routes.** ODA File Converter writes R12 and 2000–2018.
  FreeCAD 1.1 writes R14 only (its `DxfVersionOut` setting is ignored headless).
  LibreDWG's `dxf2dwg` cannot read the ezdxf sources, so LibreDWG gets a DWG
  2018 made by ODA and writes DXF with `dwg2dxf`.
- **Incomplete outputs are rejected, not committed.** A converted file must
  start with a SECTION and end with EOF. LibreDWG 0.14 silently stops after
  BLOCKS for 9 of 13 drawings in R2004+ (exit code 0); those are logged in
  `SOURCES.md`, not added.
- **Size split:** files over 5 MB go to the git-ignored `tests/corpus-private/`.
- **The exhaustive damaged-input sweep** in `tests/corpus.rs` covers only the
  small hand-written files; real-writer files are too big for every-byte
  truncation. Proper fuzzing is M2.

## M2 part A

1. **Streaming reader, borrowed tokens.** The tokenizer yields `Token<'a>`
   with the value borrowed from the input (`raw: &'a str`); the reader keeps
   one token of lookahead and copies a value only when the model stores it.
   This took the 50 MB load from 3.1 s to about 1 s; allocation was most of
   the time. `tokenizer::Token` changed shape (public API, pre-1.0).
2. **Benchmark:** `cargo bench -p cad-dxf --bench load` (no dependencies)
   times `read_bytes` on the private 50 MB file, or on a synthetic ~50 MB
   file when that is absent (e.g. in CI). It prints a warning above 2 s
   rather than failing, since CI machine speed varies.
3. **Child records are nested.** `VERTEX`s and the closing `SEQEND` live in
   `Polyline::vertices` / `Polyline::seqend`; `ATTRIB`s and their `SEQEND`
   in `Insert::attributes` / `Insert::seqend`. Children are full `Entity`
   values (own handle, layer, ...) with `EntityKind::Vertex` / `Attrib`; the
   `SEQEND` is kept as an `Unknown` entity so its handle survives. An
   `INSERT` collects following `ATTRIB`s whether or not group 66 is set.
4. **Orphaned children** (`VERTEX`, `ATTRIB`, `SEQEND` without a parent) are
   kept in place with a warning. When one repeats the handle of a child of
   the preceding entity, the warning says so.
5. **Embedded objects:** from group `101` on (R2018 `MTEXT`/`ATTRIB`
   "Embedded Object"), pairs go to `extra`, like XDATA, because they reuse
   codes the entity itself uses.
6. **`extra` stays in file order** across categories (`102` groups, embedded
   objects, unknown codes, repeats of known codes, XDATA).
7. **First occurrence wins** for codes a simple entity reads once; repeats
   go to `extra`. Codes that are lists (LWPOLYLINE vertices, SPLINE knots,
   weights and points, LTYPE elements, MTEXT `3` chunks) are read in order.
8. **Count checks:** an `LWPOLYLINE` vertex count (90), `SPLINE` knot,
   control and fit counts (72/73/74), weights vs control points, and `LTYPE`
   element count (73) must match what follows, or the record is kept
   verbatim with a warning.
9. **Text is not decoded yet.** `Text::value`, `MText::text` and attribute
   values are stored as written (not trimmed); `\U+XXXX`, `%%d` and MTEXT
   formatting codes are left for the encoding work in M2 part B.
10. **Dimensions:** group 70's low 4 bits pick the type (0–6, including
    ordinate and 3-point angular, beyond the spec's four); the remaining
    bits are kept in `Dimension::flags`. Each type reads only its own point
    codes; any others go to `extra`. Dimension variables in `DIMSTYLE` are
    kept as raw pairs (`DimStyle::variables`) until dimension rendering (M7).
11. **`DIMSTYLE` handle is group 105 only.** Group 5 in a `DIMSTYLE` record is
    the DIMBLK variable (an arrow block name), which R12 files use.
12. **Shape-file text styles** (`STYLE` with flag 1) have empty names; tables
    accept any number of empty-named entries and never look them up by name.
13. **Blocks** are a `Table<Block>` keyed by case-insensitive name. A block
    whose header can't be parsed, or that repeats a name, is kept verbatim
    (through its `ENDBLK`) in `blocks.unparsed` with a warning. Group 3 is
    dropped when it repeats the name. `ENDBLK` pairs are kept in `Block::end`.
14. **Defaults when optional codes are missing** follow the DXF reference:
    scale 1, width factor 1, text style `STANDARD`, ellipse 0..2π, MTEXT
    attachment 1, INSERT 1×1 array.
15. **Bulge maths** lives in `cad_geom::bulge` (`arc_from_bulge`); `cad-dxf`
    stores bulges as read and uses `cad-geom` only in its tests.
16. **Known-bad corpus files.** LibreDWG 0.14's R14/R2000 output (18 files)
    repeats `VERTEX`/`ATTRIB` records after their `SEQEND` and writes an
    extra `ENDBLK`, all with duplicate handles. The reader reports these;
    `tests/corpus.rs` lists the files and allows only those warnings for
    them. Every other corpus file loads with no warnings except encoding.
17. **No true aligned dimension in the corpus:** ezdxf writes
    `add_aligned_dim` as a rotated linear dimension (type 0). Type 1 is
    covered by unit tests only.

## M2 part B

1. **Nothing parsed is dropped.** Misplaced records (pairs outside any
   section, junk between tables, an `ENDBLK` outside a block, pairs before the
   first entity, pairs before the first header variable, data after `EOF`)
   are kept in `Drawing::stray` as `StrayRecord { section, index, pairs }`,
   with a warning. `index` counts the items before it in that place
   (sections, header variables, tables, blocks or entities) so a writer can
   put it back where it was. Orphaned `VERTEX`/`ATTRIB`/`SEQEND` records stay
   in the entity list as before.
2. **Unreadable tails are kept as text.** When the tokenizer hits a line it
   cannot read (a bad group code, or a code with no value), everything from
   that line on is stored in `Drawing::unparsed_tail` with a warning. The
   pairs can't be recovered past that point, but the text is not lost.
3. **`ATTDEF` is parsed** (`EntityKind::AttDef`): the `ATTRIB` fields plus the
   prompt (group 3, stored as written).
4. **Which bytes are which encoding.** The reader sniffs `$ACADVER` and
   `$DWGCODEPAGE` from the raw bytes (first 1 MB) before decoding:
   - R2007+ (`AC1021` and later): UTF-8. If the bytes are not valid UTF-8,
     they are decoded with the code page, with a warning.
   - Older files: bytes that are valid UTF-8 are read as UTF-8, silently
     (some writers, e.g. LibreDWG and FreeCAD, write UTF-8 into R14/R2000
     files that declare ANSI_1252); otherwise the declared code page is used.
   - Missing or unsupported `$DWGCODEPAGE` with non-UTF-8 bytes: ANSI_1252,
     with a warning. Bytes invalid in the code page become U+FFFD, with a
     warning (the only lossy case).
   - `Drawing::encoding` records the result: `Utf8`, or `CodePage(n)` (also
     for ASCII-only pre-2007 files, so a writer knows what to use).
5. **Supported code pages:** ANSI_874, 932, 936, 949, 950 and 1250–1258, via
   `encoding_rs` 0.8.35 (pinned; MIT OR Apache-2.0, data BSD-3-Clause).
   ANSI_1361 (Johab) and DOS code pages are not supported.
6. **Text values are decoded, originals kept.** `Text::value` (TEXT, ATTRIB,
   ATTDEF), `MText::text` and `Dimension::text_override` hold the decoded
   string; `raw_value` / `raw_text` / `raw_text_override` hold the string as
   written, only when decoding changed it (`None` otherwise, so plain text
   costs nothing extra). A writer writes the raw form when it still decodes
   to the current value, and encodes the value otherwise.
7. **Escapes decoded:** `\U+XXXX` (exactly four hex digits; surrogates stay
   literal), `\M+nXXXX` (n = 1 Shift-JIS, 2 Big5, 3 Korean, 5 GBK; 4 Johab
   stays literal), `%%d` → `°`, `%%p` → `±`, `%%c` → `⌀` (U+2300 DIAMETER
   SIGN), `%%%` → `%`, `%%nnn` → character `nnn` in the drawing's code page
   (single-byte pages only). Codes are case-insensitive. `%%o`/`%%u`
   (overline/underline toggles) and malformed escapes are left as written.
8. **MTEXT decoding keeps formatting.** In MTEXT only the character escapes
   are decoded (`\U+`, `\M+`, `%%d/p/c/%`); formatting codes (`\P`,
   `\f...;`, ...) stay, and `\\` (an escaped backslash) is left alone so
   `\\U+0041` is not mistaken for an escape. `%%nnn` is a TEXT-only feature.
9. **Names are not decoded.** Layer, style, block and linetype names are
   stored as written (after byte decoding), including any `\U+` escapes, so
   references between them keep matching. The prompt of an ATTDEF is also
   stored as written.
10. **Fuzzing.** `crates/cad-dxf/fuzz` (cargo-fuzz 0.13.2, libfuzzer-sys
    0.4.13 pinned) has three targets: `tokenizer`, `reader` (`read_bytes`)
    and `text` (`decode_text`/`decode_mtext` on every code page). It is its
    own workspace and needs nightly; it is dev tooling only, so libFuzzer's
    NCSA licence (BSD-style) does not reach anything shipped (now a rule in
    CLAUDE.md). CI does not
    run it. `tools/fuzz.sh SECONDS` seeds every target from `tests/corpus`
    and the regression inputs and runs them in parallel, without a sanitizer
    (no `unsafe` code; overflow and bounds checks stay on; about 20× faster)
    and with inputs up to 16 KB. Crashing inputs go in
    `tests/fuzz-regressions/`, which a normal test replays.
    **First 1-hour run (2026-10-10, Intel Mac, three targets in parallel):**
    no crashes, no timeouts. reader 6.7 M runs (~1,860/s, 2,905 coverage
    edges), tokenizer 209 M (~58,000/s, 103 edges, flat), text 7.0 M
    (~1,950/s, 468 edges). Peak memory 67 MB. `tests/fuzz-regressions/` is
    therefore empty apart from its README.
11. **Linear-time leftovers.** `Fields::leftovers` and the orphan-parent
    lookup no longer rescan earlier pairs/entities, so huge records can't
    make the reader quadratic.

## M3

1. **Save-back is byte-identical when nothing changed.** `Drawing::source`
   keeps the bytes the drawing was read from. `save_bytes` (and `to_bytes`
   for the same version) re-reads them and, if that gives a drawing equal to
   the current one, returns them unchanged: stray records, the unparsed
   tail, original text, formatting and undecodable bytes all survive. All
   198 corpus files save back byte-for-byte. `Source` never affects
   equality (it is provenance, not content). Cost: the source bytes stay in
   memory (50 MB for the 50 MB file), and the check re-parses on save.
2. **Edited drawings are regenerated, not patched.** A changed drawing is
   written by the generator, in R12 if it was R12 and R2018 otherwise, with
   a warning when that changes the version. Reusing the original text for
   unchanged records of an edited file is left for when editing exists (M5).
3. **Two passes: normalise, then format.** The writer first makes a valid
   copy of the drawing for the target version (handles, owners, required
   tables, block records, layouts, R12 downgrades), then formats it. Writing
   is deterministic, so read → write is a fixpoint: writing what was read
   gives the same bytes and an equal drawing (tested for the whole corpus,
   both versions).
4. **Handles.** Existing handles are kept; missing ones are assigned above
   every handle in the input; duplicates get new handles, with a warning.
   `$HANDSEED` is one above the highest handle written. R12 output has
   handles on entities, children and `ENDBLK` (as ODA writes R12), with
   `$HANDLING 1`; table entries and `BLOCK` records have none.
5. **Owners (R2018).** Computed from the structure, never trusted from the
   input: entities → `*Model_Space`/`*Paper_Space` record; block contents,
   `BLOCK` and `ENDBLK` → their block record; `VERTEX`/`ATTRIB`/`SEQEND` →
   their parent; table entries → their table. Every block gets a
   `BLOCK_RECORD`; files without layouts (R12, R13/R14) get an
   `ACAD_LAYOUT` dictionary with `Model` and `Layout1` linked from the
   records. Existing OBJECTS are copied as they are.
6. **Required content is added.** Missing defaults (layer `0`, linetypes
   `ByBlock`/`ByLayer`/`Continuous`, style and dim style `Standard`,
   `VPORT *Active`, `APPID ACAD` and every XDATA application) and anything
   entities refer to but the drawing lacks (layers, linetypes, text styles,
   dim styles, empty blocks) are added, with warnings for the latter.
7. **What generated files leave out, with warnings:** stray records, the
   unparsed tail, orphaned `VERTEX`/`ATTRIB`/`SEQEND`, unparsed table
   entries and blocks, and block records without a block. These are kept
   by save-back only.
8. **R12 downgrades.** `LWPOLYLINE` → `POLYLINE` (exact: bulges, widths,
   elevation); `ELLIPSE` → polyline (5° steps) and `SPLINE` → polyline (16
   points per knot span, NURBS with weights) via `cad_geom::curve`, 2D at
   their elevation or 3D if not flat; `MTEXT` → one `TEXT` per line,
   formatting removed, placed by attachment point; true colour → nearest
   ACI (approximate palette, `Color::aci_rgb`); lineweights, the invisible
   flag, newer codes and non-XDATA leftovers dropped; `SOLID`, `TRACE`,
   `3DFACE`, `SHAPE` kept without newer codes; other types (`HATCH`,
   `LEADER`, `MULTILEADER`, `XLINE`, `RAY`, `VIEWPORT`, ...) dropped; extra
   layouts dropped; complex linetypes become plain dashes; header limited
   to R12 variables; tables filtered to R12 groups; CLASSES and OBJECTS not
   written. Every loss is a warning, counted per kind.
9. **R12 names.** Names longer than 31 characters or with characters
   outside the code page are renamed (unusable characters → `_`, unique
   with `~n`), and every reference is updated (entities, blocks, layers,
   header `$CLAYER`/`$CELTYPE`/`$TEXTSTYLE`/`$DIMSTYLE`). Application names
   over 31 characters are dropped with their XDATA.
10. **Version-specific records.** Entities of types defined in CLASSES
    (e.g. `MULTILEADER`) are not copied into a different version: their
    record layout changes between versions and ODA drops such copies. They
    are dropped with a warning (same-version writes and save-back keep
    them). R2018 output also drops entity types that are neither standard
    nor in CLASSES (no program can read them).
11. **Encodings.** R2018 output is UTF-8. R12 output uses the drawing's code
    page (`Drawing::encoding`, else `$DWGCODEPAGE`, else ANSI_1252);
    characters outside it become `\U+XXXX` (or `?` beyond U+FFFF) with a
    warning. Text keeps its original form (`raw_value` etc.) when that
    still decodes to the current value; otherwise the value is written.
12. **Undecodable bytes are kept (fixes M2's one lossy case).** Bytes that
    are not valid in the code page are read as `U+F700 + byte` instead of
    U+FFFD, and the code-page encoder writes them back as the same byte. In
    UTF-8 output they stay private-use characters, with a warning.
13. **Formatting.** Group codes right-aligned in three columns, CRLF line
    endings, floats in the shortest form that reads back exactly (with a
    decimal point; exponent form below 1e-6 or from 1e15), MTEXT split in
    250-character chunks. `read_str` is now `read_bytes` on the text's
    bytes, so both report the same encoding.
14. **API.** `Drawing::to_bytes(version)`, `write_file(path, version)`
    (R12 or R2018; other versions are `DxfError::UnsupportedVersion`),
    `generate_bytes(version)` (never reuses the source), `save_bytes()`,
    `save_file(path)`. `cad-app convert|generate|save` exposes them.
15. **`cad-dxf` depends on `cad-geom`** (curve flattening for R12). Neither
    has UI dependencies, so the spec's separation still holds.
16. **External validation.** `tools/validate_written.py` writes every
    corpus file as R12 and R2018 and checks it with our reader, ODA File
    Converter and FreeCAD (see `tests/corpus/WRITE_VALIDATION.md`). ODA
    repairs silently instead of warning, so "opens without warnings" means:
    ODA's re-save of our file differs from it no more than ODA's re-save of
    the original corpus file does, and FreeCAD prints no problem messages.
    Result: 396 of 396 clean.
17. **Write speed is not a target yet.** The 50 MB file saves back in about
    1.5 s after loading (re-parse plus copy) and generates in about 3 s
    (R2018) or 4 s (R12).
